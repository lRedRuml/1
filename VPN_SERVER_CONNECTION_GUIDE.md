## 🏗️ Архитектура подключения

```
┌─────────────────────────────────────────────────────────┐
│  Flutter App (vpnonline_app)                            │
│  - ConnectScreen (UI подключения)                       │
│  - TunnelService (управление VLESS туннелем)           │
│  - ApiClient (запросы к backend)                        │
└────────────────────┬────────────────────────────────────┘
                     │
                     │ HTTPS запросы
                     ↓
┌─────────────────────────────────────────────────────────┐
│  Backend — shopbot (Flask API)                          │
│  Адрес: https://api.vpnonline.shop/api/v1              │
│  - /auth/login, /auth/register (аутентификация)        │
│  - /user/keys (получить ключи доступа)                 │
│  - /user/profile (профиль пользователя)                │
│  - /hosts (список VPN серверов/локаций)                │
│  - /plans (тарифные планы)                             │
└────────────────────┬────────────────────────────────────┘
                     │
                     │ Читает config + credentials
                     ↓
┌─────────────────────────────────────────────────────────┐
│  3x-ui Control Panels (управление VLESS)               │
│  Несколько панелей по локациям (DE, NL, RU и т.д.)    │
│  - Хранят VLESS ключи для каждого пользователя         │
│  - Отдают connection_string в виде vless:// ссылки    │
│  - Управляют лимитами трафика/устройств               │
└─────────────────────────────────────────────────────────┘
                     ↑
                     │ управление через
         ┌───────────┴───────────┐
         ↓                       ↓
    ┌────────┐           ┌────────────────┐
    │ Xray   │           │ Database (БД)  │
    │ прокси │           │ shopbot        │
    └────────┘           └────────────────┘
```

## 🛠️ Backend настройка

### 1. Применить security патч

Замени на сервере два файла (из `backend-patch/`):

```bash
# На сервере, где работает shopbot:
cp backend-patch/api.py      /path/to/shopbot/src/shop_bot/webhook_server/api.py
cp backend-patch/database.py /path/to/shopbot/src/shop_bot/webhook_server/database.py
```

**Важно:** это полные файлы, не patch. Если ты уже менял эти файлы после `vpnonline-security-fixes`, убедись, что поправки перенесены отдельно.

### 2. Добавить переменные в `.env` бота

Добавь в файл `.env` вашего shopbot (см. `backend-patch/ENV_ADDITIONS.env`):

```bash
# Ключ API приложения (случайная строка, генерируется один раз)
SHOPBOT_API_KEY=393b9b395689f9624a86060eee8b5584a009ac51e20bf2b2ff6020e85c9e44ac

# Gmail для отправки кодов верификации
GMAIL_USER=VPNonLineRoBot@gmail.com
# ⚠️ ВНИМАНИЕ: это НОВЫЙ пароль приложения (не обычный пароль от Gmail)
# Отзови старый пароль в: Google Account → Security → App Passwords
# Создай новый пароль приложения для Gmail
GMAIL_APP_PASSWORD=xxxx xxxx xxxx xxxx
```

### 3. Настроить платёжные системы

Платёжные ключи (YooKassa, CryptoBot) хранятся **в БД бота**, не в `.env`:

```bash
# На сервере, в директории shopbot:
python3 backend-patch/set_payment_settings.py /path/to/shopbot/users.db
```

Скрипт автоматически обновит таблицу `bot_settings` в БД с твоими платёжными ключами.

### 4. Добавить 3x-ui панели в БД

В таблице `xui_hosts` БД бота должны быть записи о панелях 3x-ui:

```sql
INSERT INTO xui_hosts (host_name, host_url, connect_host, connect_port) 
VALUES 
  ('DE-Frankfurt', 'https://de-panel.example.com:54321', 'de.example.com', 443),
  ('NL-Amsterdam', 'https://nl-panel.example.com:54321', 'nl.example.com', 443),
  ('RU-Moscow', 'https://ru-panel.example.com:54321', 'ru.example.com', 443);
```

Где:
- `host_name` — внутреннее имя (для ключей)
- `host_url` — URL внутренней админ-панели 3x-ui
- `connect_host` — хост для TCP пинга + начало VLESS ссылки (должен быть доступен с клиента)
- `connect_port` — порт для пинга (обычно 443)

### 5. Перезапустить бота

```bash
# Если используешь systemd:
sudo systemctl restart shopbot

# Или если запускаешь в Docker:
docker-compose restart shopbot
```

## ⚙️ Приложение — конфигурация

### 1. Проверить API ключ в `main.dart`

В `app/lib/main.dart` уже прописан ключ по умолчанию:

```dart
ApiClient.init(
  apiKey: const String.fromEnvironment(
    'SHOPBOT_API_KEY',
    defaultValue: '393b9b395689f9624a86060eee8b5584a009ac51e20bf2b2ff6020e85c9e44ac',
  ),
  baseUrl: const String.fromEnvironment(
    'API_BASE_URL',
    defaultValue: 'https://api.vpnonline.shop/api/v1',
  ),
);
```

**Примечание:** Убедись, что `defaultValue` совпадает с `SHOPBOT_API_KEY` из `.env` бота.

### 2. Сборка приложения

#### Вариант A: Сборка для Android (GitHub Actions)

1. Перейди в `Settings → Secrets and variables → Actions`
2. Добавь секреты (опционально, если хочешь переопределить значения из `main.dart`):
   - `SHOPBOT_API_KEY` = (твой ключ из `.env`)
   - `API_BASE_URL` = `https://api.vpnonline.shop/api/v1`
3. Запусти workflow "Build Android APK" (вкладка Actions)
4. APK готов в Releases

#### Вариант B: Локальная сборка

```bash
# Перейди в папку приложения
cd app

# Установи зависимости
flutter pub get

# Собери APK (для Android)
flutter build apk --release \
  --dart-define=SHOPBOT_API_KEY=393b9b395689f9624a86060eee8b5584a009ac51e20bf2b2ff6020e85c9e44ac \
  --dart-define=API_BASE_URL=https://api.vpnonline.shop/api/v1

# APK будет в: build/app/outputs/flutter-apk/app-release.apk
```

### 3. Платформенная настройка (iOS/macOS)

⚠️ **ВАЖНО:** VPN туннель на iOS/macOS требует специальной настройки через Xcode, которая не может быть сделана только правкой `.dart` файлов.

См. `app/NATIVE_SETUP.md` для подробных инструкций:
- Создание Network Extension сертификата
- Настройка App Groups
- Код Xcode для запуска туннеля

## ✅ Проверка подключения

### Шаг 1: Проверить backend

```bash
# Попробуй достучаться до API (замени HOST):
curl -H "X-API-Key: 393b9b395689f9624a86060eee8b5584a009ac51e20bf2b2ff6020e85c9e44ac" \
  https://api.vpnonline.shop/api/v1/hosts
```

Должен прийти JSON со списком хостов:
```json
{
  "hosts": [
    {
      "host_name": "DE-Frankfurt",
      "host_url": "https://de-panel.example.com:54321",
      "connect_host": "de.example.com",
      "connect_port": 443
    }
  ]
}
```

### Шаг 2: Проверить 3x-ui панели

Убедись, что каждая панель доступна:

```bash
# Протестируй доступность:
curl -k https://de-panel.example.com:54321/status
```

### Шаг 3: Проверить подключение в приложении

1. **Установи APK на телефон** (через `adb` или вручную)
2. **Запусти приложение**
3. **Зарегистрируйся или войди** (должен прийти email с кодом)
4. **Перейди на экран "Мои ключи"** (вкладка 2)
5. **Купи пробный тариф** (нажми "Оформить подписку")
6. **Вернись на главный экран** (вкладка 1 "Подключение")
   - Должен показаться активный ключ
   - Кнопка "Подключить" должна стать активной
7. **Нажми "Подключить"**
   - Телефон попросит разрешение на VPN
   - Разреши
   - Должна загореться индикация "ПОДКЛЮЧЕНО"
8. **Откройте интернет-браузер** → должен работать через VPN

### Шаг 4: Проверить данные о трафике

После успешного подключения:
- На главном экране должны обновляться значения "Приём" и "Отдача" (RX/TX)
- Нажми кнопку "Тест скорости" → должна измериться задержка до сервера

## 🔍 Диагностика проблем

### ❌ Проблема: "Unauthorized: Invalid or missing API key"

**Причина:** API ключ не совпадает между приложением и backend.

**Решение:**
1. Убедись, что `SHOPBOT_API_KEY` в `.env` бота совпадает с `defaultValue` в `app/lib/main.dart`
2. Перезапусти бота
3. Пересобери приложение

### ❌ Проблема: "Не удалось получить список серверов"

**Причина:** Backend не отвечает или нет доступа до database.

**Решение:**
1. Проверь, доступен ли `https://api.vpnonline.shop/api/v1/hosts`:
   ```bash
   curl -v https://api.vpnonline.shop/api/v1/hosts
   ```
2. Проверь, запущен ли бот
3. Проверь логи бота: `docker logs shopbot` или логи systemd

### ❌ Проблема: "Конфигурация сервера пуста или повреждена"

**Причина:** `connection_string` от backend невалиден.

**Решение:**
1. Проверь, правильно ли формируется `connection_string` в `xui_api.py` бэкенда
2. Открой панель 3x-ui → посмотри, есть ли там VLESS ссылка для пользователя
3. Скопируй ссылку вручную и проверь её формат (должна начинаться с `vless://`)

### ❌ Проблема: "Сервер конфигурации недоступен (4xx/5xx)"

**Причина:** URL подписки 3x-ui недоступен.

**Решение:**
1. Проверь `connection_string` — может быть URL вместо готовой ссылки
2. Убедись, что этот URL доступен с телефона:
   ```bash
   # На телефоне через VPN или с того же сервера:
   curl -v "https://de-panel.example.com:54321/sub/HASH"
   ```
3. Если 403/404 — ссылка неправильная или истекла

### ❌ Проблема: Трафик = 0 MB (не передаётся интернет)

**Причина 1:** Туннель создан, но ещё не маршрутизирует трафик (платформенная проблема).

**Решение:**
1. На Android → убедись, что приложению даны права на создание VPN
2. На iOS → см. `app/NATIVE_SETUP.md`, нужна Network Extension

**Причина 2:** Сервер 3x-ui перегружен или пользователь превысил лимит трафика.

**Решение:**
1. Проверь логи на панели 3x-ui — есть ли ошибки
2. Проверь лимит трафика для ключа в БД

### ❌ Проблема: Приложение падает при попытке подключиться

**Причина:** Ошибка в обработке VLESS профиля.

**Решение:**
1. Прочитай вывод `adb logcat | grep flutter` (если есть доступ)
2. Проверь формат `connection_string` — может содержать спецсимволы, которые нужно правильно экранировать

## 📱 Полный цикл тестирования

1. **Backend:**
   - ✅ Бот запущен
   - ✅ `.env` заполнен (API_KEY, GMAIL)
   - ✅ Таблица `xui_hosts` не пуста
   - ✅ 3x-ui панели доступны

2. **API интеграция:**
   - ✅ `curl /hosts` вернул список
   - ✅ Регистрация/логин работают
   - ✅ Получение профиля работает

3. **Приложение:**
   - ✅ Собрано без ошибок
   - ✅ Установлено на телефон
   - ✅ Может авторизоваться

4. **VPN подключение:**
   - ✅ Экран "Подключение" показывает активный ключ
   - ✅ Нажата кнопка "Подключить" → туннель стартует
   - ✅ Телефон получил разрешение на VPN
   - ✅ Браузер открывает сайты через VPN

5. **Трафик:**
   - ✅ Значения RX/TX растут
   - ✅ "Тест скорости" показывает задержку
   - ✅ IP адрес изменился на адрес сервера
