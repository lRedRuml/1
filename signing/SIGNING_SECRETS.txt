# Секреты подписи — что и куда вставить

Этот release-keystore сгенерирован для тебя (`keytool`, RSA 2048,
самоподписанный сертификат, срок действия до 2053 года — этого достаточно,
Google Play не требует конкретного CA, только чтобы сертификат не менялся
между версиями одного приложения).

## Что сделать (один раз)

Открой репозиторий на GitHub → **Settings → Secrets and variables →
Actions → New repository secret** и добавь 4 секрета:

| Имя секрета                  | Значение                                            |
|-------------------------------|------------------------------------------------------|
| `ANDROID_KEYSTORE_BASE64`     | содержимое файла `vpnonline-release.jks.base64` **целиком**, одной строкой |
| `ANDROID_KEYSTORE_PASSWORD`   | `w0d6z4hfBEiJIfoPJ1okPqcsw1CQ0lbq`                   |
| `ANDROID_KEY_ALIAS`           | `vpnonline`                                          |
| `ANDROID_KEY_PASSWORD`        | `w0d6z4hfBEiJIfoPJ1okPqcsw1CQ0lbq`                   |

(Пароль хранилища и пароль ключа совпадают — так решил сам `keytool`:
формат PKCS12, который он использует по умолчанию в новых версиях JDK,
не поддерживает разные пароли для store и key.)

`vpnonline-release.jks.base64` — открой обычным текстовым редактором,
скопируй всё содержимое (это одна длинная строка без переносов) и вставь
как значение секрета.

## После этого

Просто запусти workflow "Android Production Build" (пуш в `main` или
кнопка "Run workflow" во вкладке Actions) — он сам расшифрует keystore
из секрета, подпишет APK и положит готовый файл в Artifacts.

## Важно — сохрани `vpnonline-release.jks` в надёжном месте

Файл `vpnonline-release.jks` в этой же папке — **единственная копия**
этого ключа, которая у тебя есть. Если ты его потеряешь:
- нельзя будет выпустить обновление той же версии в Google Play (нужен
  тот же сертификат подписи, что и у предыдущей версии);
- Google Play предлагает восстановление через "App signing key
  reset request" только при определённых условиях — не гарантировано.

Сделай резервную копию (не в этом репозитории, если он будет публичным —
сам файл `.jks` и пароли из этого файла нигде не коммить, только сами
Secrets на GitHub видят их значения, но не сам файл).

## Что дальше с этим файлом в архиве

После того как секреты добавлены в GitHub — можешь удалить папку
`signing/` из своей рабочей копии/репозитория (сами Secrets на GitHub
уже содержат всё нужное), просто сохрани `vpnonline-release.jks` и
пароли из этого файла где-то отдельно и надёжно.
